# Independent cross-family audit — FT2_M5V1 stationary marginals

**Disposition:** The 16 specified high-preset files and all eight stationary enclosures withstand this audit, under the cited Claim 3, Claim 6, and spatial-eigenmeasure results. The normal fixed-bracket, unperturbed batch replay is sound on the reviewed path. The submission has fail-closed gaps in the alternate bracket CLI and the mutation-mode receipt, and the documented 38-control command does not exist. The final verdict applies to the submitted package as requested, not to the truth of the eight intervals.

## Findings requiring repair

1. **Batch accepts an empty exponent bracket and emits inverted corollaries** (`verify_all_marginals.py:36–41,49–54,111–125`; `cert_marginal.py:102–107`). Run the real high batch under `python3 -OB` with `--mu-lo 9/10 --mu-hi 1/10 --skip-trees --threads 4`. It exits **0**, emits `["9/10", "1/10"]` as its bracket, and prints the conditional intervals `["1.16717447", "-1.20360980"]` and `["0.86122409", "0.06233728"]`. Each side checks one containment inequality, and a reversed bracket passes both. Require `0 < mu_lo <= mu_hi < 1` before opening files; validate supplied expected endpoints in the pair/library path too. Also reject or explicitly diagnose inverted derived intervals. A user-supplied ordered bracket is still an external mathematical assumption, not established by this tool. No impact on the default gold2 replay.
2. **The test-only `perturb` API can mint an invalid receipt under the original digest** (`verify_marginal.cpp:321–325,353–388,1369–1384`; `cert_marginal.py:76–110,120–159`). The digest describes the original bytes, finite caps describe modified bytes, and the Python tail and optional tree oracle use original bytes. The trusted normal CLI never passes `perturb` when producing its baseline certificate. Nonetheless `combine_side(..., perturb='f', expected_sha256=...)` returns `ok: true` and a normal-looking receipt. Reproducer: keep a tiny obs-1 upper header, set theta and analytic coefficients to zero, zero every payload value except `f(J)=10^9` ticks, then request `perturb='f'` (subtracts `10^9`). The mixed receipt reports cap `1099511627776`, but the exact original `T3` drift including forcing is `1101511627776`; the unperturbed C++ cap is `1101511627776`. The exact oracle rejects the mixed receipt. This falsifies the receipt’s universal residual for its digest, not the published interval. Test perturbations should return test evidence only, with the perturbation explicit, or be applied to a frozen copy *before* all stages hash and verify it. For theta override, both math stages do use the override and the receipt prints the effective theta; the ordinary tree oracle reads nominal theta from the bytes, so it must not be used unmodified to certify that override.
3. **The promised negative-control contract is not implemented** (`README.md:70,92–102`; `cert_marginal.py:499–521,524–534`). The requested `--obs-id 1 --negative-controls` exits 2 with `unrecognized arguments`. Actual flag: `--run-mutations`. Per pair there are 16 real rejections, 20 accepted weight/parameter mutations with larger residual caps, and 2 accepted tighter-target probes with larger caps. The distinction is expected for an adaptive-error certificate, but it is false that all 38 fail closed as rejected inputs. Structural probes gate on exit 2 but do not check an applicable diagnostic; the 11 softened checks per side can treat *any* nonzero verifier return as a successful detection, including abnormal termination. The actual executed runs produced the intended diagnostics / larger caps and no sanitizer log. Fix the replay command and document the actual result, and require expected diagnostics or explicit successful widened results instead of folding runtime failure into detection.
4. **Smaller submission errors:** README line 13 gives `50,204,104` rows instead of `49,204,104` per endpoint; the `8,035,467` envelope checks are computed once, independently of lambda, and used at both endpoints. README line 36 overstates what overlap shows: it is a consistency check, not proof of zero mass at `(2,0)`. Header comments at `marginal_format.hpp:15,27,40` use a different convention for `w` and an obsolete tail constant. README line 67 names `m5_obs_val`, but the function is `m5_eval_obs`. `verify_marginal_tail.py:150–155` is tail-only, not full snapshot validation; this is worth stating in its CLI help. Batch `--skip-trees` intentionally omits the extra sample checks, not the exact inequalities.
