## Reproduction

From the release root, use `bash round2/verify/astra/run.sh joint-cold` or `bash round2/verify/astra/run.sh joint-preflight`. They select one permitted CPU and use external scratch via `TMPDIR`. The commands and scratch layout described below are the historical source-checkout instructions; `quick` requires raw and mbar snapshots, which are not supplied in the release.

From a checkout containing the paths in [inputs.txt](inputs.txt):

```sh
taskset -c 3 python3 -B round2/joint-enclosure/replay.py
```

Needs Linux, Python ≥3.11 with NumPy, GCC with C++20 and UBSan, GMP development libraries, Bash, and GNU coreutils/time. Use a Python executable with NumPy already installed. The split replay uses a 5 GiB virtual address cap; the two frozen raw snapshots are about 612 MB each. Allow several GB of free scratch space. Paths hardcoded by the upstream programs are resolved in a disposable source tree inside `round2/joint-enclosure/`; the original scripts and manifests are read only. All raw snapshots, mbar, executables, projections, and per-stage logs are scratch files. Raw snapshots and mbar are rebuilt by the occupation-tail replay before the same bytes are linked into scratch for the other two modules. The three unsigned profile generators per side must match the decompressed frozen files byte for byte; the unchanged compressed inputs are then used by the original input-restricted checker because it hashes the compressed bytes. An independent Python layout comparison checks all six profiles and the mbar values and tail coefficients in K7/144 scope.

The full cold replay passed on CPU 3 in 3193.65 seconds (53 min 14 s). It rebuilt both raw snapshots, repeated their exact and mutation checks and mask63, independently reproduced both five-pass totals and all 50 rank counts, re-created the K7/144 profile contents and checked both exact price sheets, then reproduced the stated fractions and rejected all nine composition plants. The five-pass stages took 1117.03 seconds for the lower sign and 1344.81 seconds for the upper sign. See replay-status.md for the scope and chronology of the reviews and replays. Separate renewal work is recorded in the source checkout at `round2/joint-enclosure/renewal-progress.md`.

For a short run on the current raw and mbar snapshots, use:

```sh
taskset -c 3 timeout 14s python3 -B round2/joint-enclosure/replay.py quick
taskset -c 3 timeout 14s python3 -B round2/joint-enclosure/replay.py preflight
```

`quick` checks hashes of the snapshot inputs and frozen certificates, verifies the split transcript and recomputes the exact composition with planted failures. It trusts the reviewed upstream frozen transcripts and does not rerun the solvers or the dual model. `preflight` copies the cold input allowlist into an empty tree, checks the original prior and Python imports there, and checks the two frozen sheet identities. It needs neither NumPy nor raw/mbar.

Using existing raw snapshots in separate pinned pilots, both mbar tables and their tail coefficients regenerated byte for byte in scratch, as did all six decompressed profiles. The Python K7/144 checker separately accepted 979,299 mbar values per sign and the associated finite, overlap, conditional, and affine-tail rows. These are component results; they do not stand in for the full cold replay.

To check staging locally, `taskset -c 3 timeout 14s python3 -B round2/joint-enclosure/check_export.py` exports the tracked inputs from `HEAD`, adds only the listed pending paths and replay code, reruns preflight there, and scans all 13 C/C++ translation units for missing headers.
