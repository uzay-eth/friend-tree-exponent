# Refined lower endpoint of the exponent

This folder checks the lower endpoint of Theorem 2 of the [paper](../../paper/friend-tree-exponent.pdf):

$$\frac{3843726496355222669}{6794465353700000000}\le\mu\le\frac{127993535256830043}{226242120050000000},$$

or $0.565714341933\le\mu\le0.565736986679$ rounded outwards. The upper endpoint is the unchanged five-vertex (Gold2) upper endpoint. The lower endpoint comes from a larger lower table of the same format, accepted by the unmodified verifier and combined class by class (Lemma F.1 in Appendix F of the paper). The unmodified combiner on the same table certifies only $3843725577155222669/6794465353700000000<99/175$.

Consequences, checked in exact arithmetic: $99/175<\mu<142/251$; since these are Farey neighbours, a rational $\mu$ has reduced denominator at least 426. The fraction $241/426$ lies inside the interval and is not excluded.

## Files

| File | What it is |
|---|---|
| `check_ratio.py` | light, fail-closed check of the receipt arithmetic; standard library only |
| `receipt.json` | lower-mode receipt from the unmodified checker and verifier on the witness (SHA-256 `f46b5f8d…`) |
| `classes.txt` | per-class data, one row `c min_value max_hosted_cap` for each core degree `c = 1..4095` (SHA-256 `278c423e…`) |
| `verify_ratio.patch` | four read-only lines, in three places, added to the repository verifier to write `classes.txt` |
| `replay_full.sh` | full, fail-closed replay on the 13 GB witness with the undefined-behaviour sanitizer |
| `ubsan_probe.cpp` | planted signed-overflow control: the sanitizer must catch it before the real runs start |
| `set_alpha.py`, `builder_threads.patch` | used to regenerate the witness (below) |
| `MANIFEST.sha256` | digests of these files and of the repository verifier sources they use |

The verifier, tail checker, combiner and builder are the repository files in [`round2/proofs/neon2/quintet-cert/`](../../round2/proofs/neon2/quintet-cert/); nothing is copied.

## Light check

From the repository root:

```sh
python3 -I verify/refined-lower/check_ratio.py --self-test
```

It authenticates `receipt.json`, `classes.txt` and the Gold2 receipt by SHA-256, requires an accepted lower-mode receipt for the witness digest, parses every class row, recomputes $\kappa=1907/67944653537$ and the endpoint exactly, and checks the Farey arithmetic and the outward decimals. Eight planted defects must each be rejected. It ends with `RESULT: PASS`. It does not rerun the drift verifier.

## Full replay

```sh
bash verify/refined-lower/replay_full.sh WITNESS NEW_OUTPUT_DIR 6
```

`WITNESS` is the 13,046,351,000-byte lower table with SHA-256 `80e3b80a9f962b458854828abab5b00e2806a6c1ce709835b5e884b0afd4ad28`. `NEW_OUTPUT_DIR` must not exist. The script checks `MANIFEST.sha256`, the witness digest and its lower-mode header. It patches a copy of the verifier and checks the patched digest `f85a172a…`, and compiles with `-fsanitize=undefined -fno-sanitize-recover=all`. A planted overflow must be caught first. Then the instrumented verifier must exit 0 with empty standard error, reproduce the receipt's verification record, and write a per-class file byte-identical to `classes.txt`. The unmodified checker on the unmodified verifier must reproduce the stored lower receipt and its tree oracle exactly. It ends with `FULL REPLAY PASSED`. Needs g++ with C++17 and OpenMP, `patch`, GNU `time` at `/usr/bin/time`, Python 3.10+, and about 14 GB of RAM.

## Regenerating the witness

The witness is not stored in the repository. It was regenerated byte for byte by the repository builder with `builder_threads.patch` applied (a thread-count setting only), run as

```sh
LANE_NT=8 ./build_quintet gold3 lower quintet_lower.bin
python3 -I verify/refined-lower/set_alpha.py quintet_lower.bin 302884234
```

Before the header patch the file has SHA-256 `62d4823d592422dbc586d6f475b15d43e91a13cc18aa621d25b2c5f12761dcbe`; after it, `80e3b80a…afd4ad28`. `set_alpha.py` writes only the lower-mode comparability numerator in the header; the verifier recomputes everything from the patched bytes.

## Provenance

The classwise aggregation and its application were first written as a research note (SHA-256 `9e08e866a13156df08909faa37277b1c0b99415d870b1c191955c6e2ae169f70`), not part of the repository. Appendix F of the paper is a write-up of that note with the same scope. A GPT-family referee found the classwise lemma, the host allocation, the tail classes, the exact endpoint and the Farey bound all hold; a separate Claude review also passed. No human has refereed it.
